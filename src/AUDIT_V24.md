## 3. GRI 算法（替代旧 ALNS）

### 3.1 架构
1. 零 LP 岛搜索：6 独立岛、D1–D9、双策略贪心评估、定期迁移。
2. 一阶精确抛光：全邻域精确评估 + ILS（有界）。
3. 二阶联合抛光：开闭/退役/时间尾段动作 × 减容，含前缀与单期调整。
4. 所有报告值由精确 LP 计算；配置必须通过 `config_violations`。

### 3.2 贪心评估器定位
- `greedy_recourse.py` 成功时构造可行流，成本为认证上界。
- 多期库容协调使单遍构造保守；双策略（premium/maxsort）提高覆盖识别。
- 贪心仅用于搜索与排序，不用于论文最终精确数字。

### 3.3 已验证的精确命中
- 文件：`experiments/config_gri_polished_test.json`
- 固定回 CPLEX 重解目标：853903997.6484964
- 与 `results_gri_small_cplex.csv` 的 real 精确最优完全一致。
- 另一独立端到端种子 gap=1.017%，说明必须多种子报告 best-of-K + 命中数 + 均值。

### 3.4 负 gap 事件（已作废）
- 前缀减容未保界，产生 z=-1/-2；LP 求值器未检查一阶定义域，造成虚假负 gap。
- 修复：`repair_monotone` 统一夹紧 0≤z≤4；新增 `config_violations`；验证脚本全部经有效性门禁。
- 任何负 gap 一律视为 bug，不作为算法优势报告。

## 3.5 参照最优的证书强度
- 默认 MIP 相对容差 1e-4 对 gap 比较太松。`cplex_saa.build_and_solve_saa` 新增 `mip_gap` 参数。
- `results_gri_small_cplex_tight.csv`：11 实例在 mip_gap=1e-9 下全部求得 **MIP gap = 0.0**（已证明最优），单实例 20–43s。
- 目标值与 1e-4 容差版完全一致，说明原参照已经最优；现在证书更强。
- 因此 GRI 的 gap 是对**已证明最优**的精确算术差，不是对近似解的估计。

## 5. 实验协议错误与更正（2026-10-27，重要）

**错误**：规模阶梯初测时同时启动 4 个 CPLEX 进程，每个默认吃满 32 核，
实际各得几分之一算力。结论"CPLEX 在 m=4/6 无解"由此而来。

**更正（独占重测）**：
- m=4 clone 实例：CPLEX 600s 给出 2.908e9，gap 0.08%
- m=4 hetero 实例（容量跨 2 倍、成本 ±45%、距离 σ=0.32）：688s 可解
- 三种 MIP 强调模式（默认/可行性/隐藏可行解）结果一致 ≈2.908e9，
  说明不是参数问题，是算力问题
- 主表 12 个慢格子重解：5 个曾显示 gap 0.17–0.44%，隔离后全部 <1e-4
  （3–297s）。`results_main_exactfix.csv` 记录；主表 CSV 已回填修正值

**教训**：并行跑求解器必须显式限核（`mdl.parameters.threads=k`）或用进程数
≤ 物理核数/线程数。墙钟时间在超订下不可比。论文 §6 已写明隔离协议。
